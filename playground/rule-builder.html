How to use this new here? start here

You write rules that rewrite a prompt before it's encoded. Define your character once — her hair, eyes, outfits, the conditions they appear under — and the engine transforms a short prompt into the full one, every time.

Quick start

  1. Pick a profile (top-right): Anima · prose for section-based prompts, or Booru · tags for comma-separated tags.
  2. Edit the rules on the left — the seeded celica sheet is a working example.
  3. Type a test prompt in Input · positive; the Output and trace update live.
  4. Hit Export YAML — that's the character-sheet file the ComfyUI node will load.

Every rule is four ideas

  • when — the condition that gates the rule (e.g. any_of: celica). always = no condition.
  • into — where new tags go: a section like clothes, or * for the single tag list.
  • mutation — what it does: add, add_negative, remove, set, tmp.
  • Rules run top → bottom; groups and switches nest.

Rule types

tagAdd / remove / set tags. The everyday rule.
groupRun all child rules under one shared when + into. Keeps related rules together.
switchRun the first matching child, else the default. Mutually-exclusive — perfect for picking an outfit.
swapReplace a placeholder tag with expanded tags at its position.

Conditions (when)

any_offires if at least one listed tag is in the prompt
all_offires only if all are present
none_offires only if none are present
alwaysno condition — always fires

Mutations

addappend to the positive prompt (deduped — never doubles a tag)
add_negativeappend to the negative prompt
removedrop a tag — stays visible to later rules, gone from output
setoverwrite a whole section (Anima mode)
tmptemporary tag: visible to later rules, not rendered

Reading the trace

The trace shows exactly what fired and why — the engine's killer feature:

> group / switch $ tag / swap ? condition result + added - removed = set ~ temporary x skipped

Pro tip

Put your character's activation word (e.g. celica) in the prompt to fire her rules — then add a remove: celica rule so the name never reaches the model (it doesn't know it, and might misread it). In the real node, a picker button will insert that word for you.
