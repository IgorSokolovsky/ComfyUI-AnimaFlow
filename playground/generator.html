Anima Generator + Anima Preview

playground mockup · docs/generator-design.md
Behavioural reference for the two nodes in AnimaFlow/Anima. Everything here is clickable — toggle stages and watch the three image outputs re-resolve, flip use_internal_loaders and watch the resource sockets go dead, wire a sampler field and watch its overlay row flip to driven by wire, add detailer blocks and watch their SEGS override sockets appear, hover the compare to wipe. Same palette as playground/theme.html; nothing here fetches anything.
The socket rows here are representational — do not port them. This page has no litegraph, so it has to draw the input/output sockets to show the design. A real node doesn't: litegraph draws every socket itself from INPUT_TYPES/RETURN_NAMES, in its own column. Porting these rows literally is what produced the "every socket rendered twice" bug on 2026-07-28 — the node came out twice as tall, listing every socket name once as a real dot and again as a fake one. The body renders only what litegraph doesn't: the settings rows. js/anima/test_resize.mjs §C2 now fails if a socket row comes back.
Mockup, not the node. The images are procedural SVGs standing in for real stage output — they differ in resolution on purpose (1024 → 2048), because that mismatch is the thing the wipe has to survive. Litegraph resize, socket typing, and the settings-blob round trip are all out of scope here.

Open questions this mockup exists to settle
Open · one tabbed overlay, or five dialogs Upstream ships one dialog per stage — five files, ~130k of JS (web/js/aio/*_settings_dialog.js). This mockup implements the single tabbed overlay alternative. Click any ⚙ to judge it. The tab strip carries a dot per enabled stage, so "what's actually on" is readable without opening anything.
Changed · settings are a right-side drawer Not a centred modal — a modal covers the graph you're tuning against, which defeats having the node on screen. The drawer is 460px, so the overlay is one column; two crushed every label. Upstream ships five separate centred dialogs; this is one drawer with a tab strip.
Settled · sampler values, wired wins per field No use_internal_sampler flag. Each of seed / steps / cfg / sampler_name / scheduler is its own socket; wired drives, unwired falls back to the overlay. Toggle wires in the Sampler tab and watch the fields flip to driven by wire — the badge exists because an editable number that's silently ignored is the one real risk of this pattern.
Settled · the detailer detects for itself An earlier draft had this node take SEGS as its only way in. That was wrong twice: DetailerForEach is an Impact node, so the stage needs Impact either way — and SAM3_Detect is a ComfyUI built-in, so owning detection costs no dependency at all. Pushing it out bought nothing and cost you a hand-wired detector chain per block, in the one node whose point is not wiring a pipeline by hand. Now: detect_prompt per block and no SEGS sockets at all — an override socket was briefly kept and then dropped too, on the same grounds as lora_stack: speculative wiring nobody asked for. Appendable if a real need appears.
Settled · no LoRA node of our own We don't build a stacker and the Loader Panel gets no lora row — Pixaroma's node already does it, and in the Loader Panel it would have broken that node's one-row-one-slot invariant. LoRAs arrive already applied to MODEL/CLIP, or from this node's inline list when use_internal_loaders is on — turn it on and a LoRA tab appears. control-panel-design.md §3b records the rejection so it isn't re-proposed.
Settled · no lora_stack socket at all Checked by pulling the clone to v1.4.62. It does stack — many rows, each with a switch and strength, applied in order. What it doesn't do is emit a LORA_STACK object: it returns patched MODEL + CLIP + triggers. So the normal path needs nothing from this node: Loader Panel → LoRA Loader Pixaroma → Generator.model. The lora_stack socket is therefore gone — it was speculative compatibility for packs that emit one, in a pack built for a setup that doesn't. Two ways in, matching the two resource modes: baked into MODEL/CLIP, or the inline list. Append it later if a real need shows up.

The trap: route the patched CLIP on to your text encode. Wire the raw one and the LoRA's model effect still lands while its CLIP effect vanishes — no error, just a weaker result.
Settled · MAX_DETAILER_PASSES = 4 Upstream is N addable blocks, not two — face/eye built in, custom_N beyond them, all renameable and reorderable, effectively uncapped. The Detailer tab mirrors that, with each block owning a SEGS socket in place of upstream's per-block detect_prompt. Capped at 4 — every pass is a full re-sample. The cap may grow later, never shrink.
Settled · pass-through on a disabled stage A disabled stage's output carries the previous stage's image. The resolver above spells out which, and flags in amber when two outputs are carrying the same tensor — so image_mid == image_base reads as a documented state, not a bug.
